## やり方

- **読むだけ。** 点検中は DATA・analyses・スクリプトを変えない。直すのは点検が終わってから、別の作業として
- 範囲を領域に分ける（例: 台帳 / ビューア / 速度論 / 相の判定 / 論文の図）
- コードを読むだけで終わらせず、**生データから別のコードで数値を出し直して**、解析の出力と比べる
- 探す誤りの型: 並び順の取り違え、名前（ファイル名・列名）の読み取り、補間で埋めた値、決め打ちの定数、
  絞り込みの条件（片側だけ・抜け）、表の結合のずれ、単位、時刻の基準（タイムゾーン・書き出し時刻）、途中で止めた測定
- 検算のスクリプトは `scratch/audit-{{slug}}/` に置く（消えてよい場所。要点はこのメモに書く）
- `labkit check` の結果（reports/check_report.md）も最初に見る

## 記録

点検が終わったら、確かめた解析ごとに結果を残す:

```bash
labkit verify <ana_id> --result ok      --method "生データから別実装で再計算して一致" --report notes/audit-{{slug}}_{{date}}.md
labkit verify <ana_id> --result error   --method "…" --note "段の境界が前にずれる（12/661 本）" --report notes/audit-{{slug}}_{{date}}.md
labkit verify <ana_id> --result caution --method "…" --note "n の CI が狭すぎる（点の相関）"
```
